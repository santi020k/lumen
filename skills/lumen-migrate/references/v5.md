# Lumen 5 migration

Verify installed versions and target registry availability before updating a consumer. Web adapters
are runtime-only; install the target @santi020k/lumen CLI separately as a development dependency.
Candidate evaluation uses local packages from one reviewed revision and is not publication evidence.

Request `lumen_get_migration` with `targetVersion: "5.0.0"` before filtering packages. From the matching
CLI, preview `lumen migrate v5 --cwd <consumer> --dry-run --json`. V5 performs no automatic source
rewrites. It separates compatibility review signals from optional adoption; it never replays v4
spacing or SDK transforms. Run older migrations separately when crossing earlier major boundaries.

Dependency changes require an explicit `--dependencies --apply` request. The existing automated
rollout requires pnpm and follows the bundled v5 release manifest, including independently versioned
companions. Other package managers retain their own manual manifest and lockfile workflow. An
explicit `audit-consumer --version` target must match the bundled release version. Never fabricate
5.x pins for companion packages, or infer publication from local metadata. Native pins remain app-owned.

Required review: await Astro's `LumenInitUiPrimitives(scope)` before consuming enhanced markup;
observe `ui:ready`, handle initialization failures, and account for asynchronous toast rendering.
Check reveal thresholds, tall/clipped content, keyboard focus and reduced motion.

Optional adoption: Astro automatic CSS, React/Elements foundation plus component CSS, verified
selective exports, styling parts, and editable product recipes. Include compound and dynamically
created markup. Existing root exports and full styles.css remain supported. Recipe copies belong
to the application and are not silently updated by package upgrades.

Retain local patches until equivalent consumer tests pass. Check types, zero-warning lint, tests,
builds, navigation, cold interactions, failed assets, phone/desktop, RTL and enlarged text. The
source-only doctor cannot prove browser asset delivery. Explicit rendered audits require a running
local app and caller-installed Playwright. Restore the consumer manifest, lockfile, setup and patches
together for recovery; never move a published tag.
